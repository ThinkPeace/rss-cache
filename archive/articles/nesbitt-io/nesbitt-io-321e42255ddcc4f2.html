Releases, advisories, and articles from across the package management world

This week’s package management news, gathered from the package manager OPML feed collection, my posts and boosts on Mastodon, and anything people sent me. Version control and forge news is in the Wednesday This Week in Source Control roundup.

Security

Hex.pm disclosed that on 23 November an attacker ran commands on its web servers through CVE-2026-129514. The decoder for the application/vnd.hex+erlang content type ran before routing and authentication, and accepted maps with a __struct__ key. A crafted struct then reached error reporting code that applied a module, function and arguments taken from the request. The attacker sent 69 requests over 13 minutes before all six servers were replaced with a patched build.

The team checked packages and the database and found both unchanged. All 23 releases published during the incident match audit log entries, and package and registry files match their checksums. Database reads are not logged, so email addresses, bcrypt password hashes and 2FA secrets may have been read.

Hex users should change their password and reset 2FA, and until a Hex client release with a new signing system arrives in the coming days, the post advises fetching from repo.hex.pm rather than mirrors. Ash 3.38.0 fixes a related bug, CVE-2026-124283, where keyset pagination accepted crafted structs in client cursors.

Composer 2.11.3 and 2.2.33 fix GHSA-374h-4mh9-7rpm, a bypass of the fix for CVE-2024-24821. Running Composer in a directory with an attacker-prepared composer.json and vendor directory could execute code as the current user, even through read-only commands such as composer validate. Package descriptions, support links and licence names are also no longer rendered as console markup.

pnpm 12.23.0 to 12.24.0 and 11.29.0 stop reading otp from config files, which a repository could use to leak ${NPM_TOKEN} to its own registry. Both branches reject file: and link: dependencies declared by registry packages and send registry credentials only over HTTPS or loopback HTTP. --minimum-release-age is now also a command line option.

A tarball with a malformed PAX header could install different files under pnpm and npm, a parser differential fixed in 12.x. Platform variants are removed in 12.x as well, so maintainers who publish them have to switch to optionalDependencies.

Flatpak 1.18.6 fixes a bug where an app, runtime or extension with extra-data could create setuid root files on the host when installed (CVE-2026-133842), and a sandbox escape through file descriptor passing in flatpak-portal (CVE-2026-133845).

Docker Engine 29.10.1 fixes CVE-2026-135124, where a process in a running container could make a read-only bind mount writable during docker cp and have the copied files modify the host directory. It also fixes unbounded reads when parsing user, group and ID mapping files (CVE-2026-135844).

uv 0.13.10 fixes GHSA-vjvj-3m3f-fgmm, a low severity parser differential. A ZIP with a data descriptor and an understated compressed size in its central directory installed a full file under uv and a prefix of it under pip. uv now rejects archives where the two sizes differ. The release also validates that dependency requirements in uv.lock match the locked package versions.

Releases

Renovate 45.0.0 to 45.3.2 is a small major release, the first planned one since 43 in January. In pnpm projects, security updates now go through pnpm’s release age check. The automatic minimumReleaseAgeExclude entry they used to get let a malicious “fix” attached to a published advisory skip it. The old behaviour is opt-in through toolSettings.pnpmMinimumReleaseAgeExcludeSecurityUpdates.

The flux manager now supports OCIRepository chart templates in HelmRelease resources.

mise 2026.11.12 to 2026.11.14 adds mise audit, which checks installed tool versions against OSV.dev and exits 1 on findings. mise upgrade --vulnerable upgrades only the affected tools. An experimental cache.sandbox option uses Landlock on Linux to fail a cached task when it reads or writes outside its cache declaration.

vlt 1.9.0 adds vlt stage publish, which uploads a version to the registry as staged, to be published once a maintainer approves it. The list, view, approve, reject and download subcommands manage staged versions. vlt trust github sets a GitHub Actions workflow as a trusted publisher for a package.

pixi 0.85.0 renames the platform key in workspace platform definitions to subdir, with the old key still accepted under a deprecation warning. Dependencies on virtual packages can now use operators other than >=, and pixi tree has a --json flag. Lock files from older versions may need a fresh pixi lock.

The winget 1.30 release candidate adds source priorities through winget source add --priority, an --output-locale option on every command, and --ignore-unavailable on install to continue when some packages are not found. An experimental setting shows numbered choices when several packages match a single-package command.

Yarn 4.19.0 prints registry notices from all commands that change registry state, isolates npm metadata caches by registry URL, and supports Node.js 28 in the PnP ESM loader.

packaging 26.4 drops Python 3.9 and adds prepare_environment() and Marker.evaluate_prepared() for evaluating many markers against one environment. VersionRange adds from_bounds(), snap_bounds() and relation(). Henry Schreiner reports that around 40 of the project’s 46 benchmarks got faster.

zizmor 1.33 adds a dangerous-checkout audit, which flags actions/checkout steps that set allow-unsafe-pr-checkout: true. The impostor-commit and ref-confusion audits now account for workflow lockfiles.

Poetry 2.5.2 fixes poetry install building an sdist before checking it against its lock file hash.

Homebrew 7.0.16 to 7.0.17 enforces the attestation trust policy. Basic credentials on a download are now sent only to the source URL’s origin and are dropped when a redirect goes to another origin.

pipx 1.19.0 to 1.19.2 shows each environment’s shell completions in pipx list and flags missing or misplaced completion files.

Articles

Transparency log & first stage of organizations (Igor Benko, Packagist blog) describes an append-only public log of security-relevant events on Packagist: maintainers added or removed, packages transferred, versions created with their commit reference, and blocked attempts to change a reference. The work was funded by the Sovereign Tech Fund through the PHP Foundation.

Stable versions have been immutable since June, which the post says would have blocked the April attack that force-pushed a malicious commit behind the 5.0.2 tag of intercom/intercom-php. Organisations with individual member accounts are partly live. A tamper-evident design that would detect changes made through a compromised Packagist database is in development.

Nils Adermann and Jordi Boggiano’s SymfonyCon Warsaw slides list the year’s attacks on PHP packages and a 2027 roadmap. Alpha-Omega is funding artifact integrity work in five phases:

  • Packagist stores Zstd archives of all tagged versions with checksums
  • Composer verifies Sigstore signatures and build provenance
  • Scoped API tokens with expiry
  • Trusted Publishing from chosen CI workflows
  • A composer publish command with staged releases approved by hardware key

FIDO2 security keys and passkeys are due on Packagist in the coming weeks. The funding slide lists 2026 running costs of about $1M and roadmap work of about $1.4M. Private Packagist and a sponsor programme launched in July each contribute around $500K. Packagist served 7.4 billion installs in October, up from 3.1 billion in October 2025.

Content-Addressable Gems (Jenny Shen, RubyGems blog) explains the RubyGems 4.1 feature where a precompiled gem is built for a single Ruby ABI and named by a prefix of its SHA-256, such as rubydex-0.4.4-aff68219.gem. A platform gem bundles one copy of the extension per Ruby. Maintainers can publish a build for a new Ruby under the existing version number. Lockfiles have new CONTENT ADDRESSES and RUBY ABIS sections, and older clients skip these gems.

Securing Python projects from supply-chain attacks (Konstantin Schütze, Astral) lists nine measures with the configuration for each. They include pinning GitHub Actions to full SHAs, Trusted Publishing behind an environment that requires approval, three-day dependency cooldowns in uv, Dependabot and Renovate, locking CI tools and scripts with uv lock --script, and no-build = true to install from wheels only.

Needles, Haystacks, and Numbers Between 0 and 1 (Adam Harvey, Rust Foundation) reports on an experiment that scores every newly published crate file from 0.0 to 1.0 for whether it looks malicious. Humans review every flagged crate.

It scanned 135,548 crate files published between 11 and 21 November. Four crates scored 0.9 or higher and all four were malicious. Lowering the threshold to 0.35 flagged 332 crates, and the same four were the only malicious ones. A false-negative evaluation is planned for January 2027.

GitHub’s new “Security Advisory Permissions” feature (Seth Larson) describes the change from the Python Security Response Team’s side, which was in the private beta. Before it, only repository admins could score severity, close duplicates, assign CVE IDs or publish an advisory, so triage fell to a few highly privileged people. Several PSRT members now triage more actively.

Allowing Nix packages to override your version in Go (Jamie Tanna). Nix builds have no .git directory, so Go’s VCS-derived build info is empty. He declares a version variable that packagers set with -ldflags='-X main.version=1.2.3' and falls back to debug.ReadBuildInfo() when it is unset.

GitHub Actions accepts invalid YAML (William Woodruff). GitHub runs workflows containing a multi-line single-quoted scalar whose closing line is indented at the same level as its parent key, which YAML 1.2.2 forbids. zizmor rejected a real workflow for this, and he suspects a guard in YamlDotNet that only fixed the double-quoted form.

Farid Zakaria’s trynix.dev now runs GUI programs from Nix packages, including Firefox, in a browser tab. It uses unkernel, a Linux kernel compiled to WebAssembly, so only user programs are emulated. Browser tabs as a container runtime builds an OCI runtime called tabc on the same base. docker run --runtime tabc alpine runs each container in a Chromium tab, with no Linux VM on macOS, at 11 to 36 times slower than runc.

Your phone is a Kubernetes node (Farid Zakaria) describes tabernetes, a k3s cluster where each browser tab that opens the join link joins as a node and runs pods through tabc.

Elsewhere

PEP 847, Problem Details for the Simple Repository API, was accepted on 23 November. Indexes should send RFC 9457 JSON bodies with Content-Type: application/problem+json on error responses, so clients can show a specific reason for a failure. Hugo van Kemenade notes that it is the first PEP accepted by the new Python Packaging Council.

The Software Stewardship Lab announced seven research programs, each funded through Open Collective. They include an annual report on maintainer well-being, a study of AI’s effect on maintainers, work on Python’s binary dependencies and on declaring non-Rust dependencies in Rust packages, an observatory for critical projects at risk of being unmaintained, and a growth fund for ecosyste.ms, which I run.

What is an OSS Ecosystem Steward, and can we have one? (Salve J. Nilsen, London Perl & Raku Workshop) proposes a community-owned European cooperative to take the Cyber Resilience Act’s open source steward role for CPAN. Manufacturers would pay subscriptions for attestations issued by maintainers and signed by the steward, with the money passed on to members.

Considering open source viability for digital sovereignty (Dawn Foster) argues that swapping a proprietary vendor for single-vendor open source trades one dependency for another, and points to the CHAOSS practitioner guide on assessing viability.

Josh Bressers talked to Sivana Hamer about software attestations and in-toto on the Open Source Security podcast.

The Sovereign Tech Agency’s survey for the EU Sovereign Tech Fund pilot closes on 30 November. It asks respondents to name up to three important open source projects or technologies and say why they matter.

Where the money goes (Invest in Open Infrastructure) tracks $663M of grants to 94 open research infrastructures from 47 funders between 2001 and 2026. Of that, $192M went directly to infrastructures and $411M to research that depends on one.

Alpha-Omega published a case study on Volker Dusch’s work as the PHP Foundation’s Security Engineer in Residence during the PHP2Shell response in October. The security team received more than 200 advisory reports in one week. He handled the daily calls with outside security teams and the outreach to Linux distributions while PHP’s engineers wrote the fixes.

That’s not a project (Joe Brockmeier) says LWN now receives two or three pitches a day for projects generated with an LLM over a few days or weeks, up from one or two news tips of any kind a week. LWN turns these pitches down, because the abandon rate is high and each project’s community is one person with an LLM subscription.
