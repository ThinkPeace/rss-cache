One of the questions in response to the Microsoft employee price list from 1987 came from Peter Cooper Jr.:

Why is the MS-DOS BASIC Compiler cheaper than the MS-DOS BASIC Interpreter?

That’s a good question. You’d think that since the compiler is more powerful, it should cost more.

And it probably did cost more in stores.

But this is the employee price list, and the policy for employee pricing at the time was to charge for cost of goods plus some administrative overhead for running the employee software program itself.¹

I don’t know why the MS-DOS BASIC Compiler packaged product cost less to produce than the MS-DOS BASIC Interpreter, but I can guess.

I bet the manual is thinner.

The compiler product assumes you don’t need a tutorial on the BASIC language itself. The compiler manual concerns itself with instructions on how to run the compiler and details on how the compiled version of the language differs from the interpreted version. (For example, there may be some interpreter features that aren’t supported. Or there may be special comments you can put in your program that are used as directives to the compiler itself and which are ignored by the interpreter.)

A thinner manual requires less paper and a smaller box, and it weighs less, which means that it costs less to produce, ship, and store.

¹ This is no longer the policy for employee pricing. Employees can no longer, say, get Windows Server Datacenter Edition for the price of a cardboard box and a DVD.
